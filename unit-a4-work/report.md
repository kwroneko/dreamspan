# ST fork-name reconciliation, round 4

Branch: `unit-a-fix4`, based on `16f94cb`. No spec changes or push. Fixtures are synthetic; no owner chat logs or card definitions were read.

The two findings in `verify3.md` are now regular tests in `packages/server/test/stImportNamePlacement.test.ts`. Before the fix, all six N3 variants failed (automatic filename, shared-history writer/swipe replacement, and custom-to-automatic filename), and all three N4 variants failed (imported name, local rename, explicit clear). Evidence: `repros-before.log`. The clear cases also check that a subsequent custom ST filename cannot restore the cleared name.

Reconciliation now receives parent context even when ST supplies no custom name. A remembered naming choice stays on its slot while that slot remains on the file's path, including when a parent adopts it. A replacement path receives both the name and `branch_name_user`; only its redundant suffix copy is cleared. Original recorded paths retain their naming decisions. The invariant and the parent-adoption behavior are documented beside reconciliation and in ARCHITECTURE.md §13.

An additional upgrade regression simulates automatic-filename records written without `named` or `nameSlot`. Both local name and clear failed before recovery from the prior path was added (`legacy-before.log`).

The seeded test creates synthetic main, custom, automatic and nested fork files. Seeds 41, 871 and 20261026 each generate 30 edits, shuffling all ten edit families: writer, swipe, message deletion/addition, filename change, file removal/restoration, local rename/clear, and a parent extension through its child's switch point. After every file import, an independent before/after graph oracle checks placement, both naming fields, original-slot naming, preservation of every other source record, and label uniqueness along every recorded path. It checks unchanged folder replay too. Failures are replayed in fresh folders while deleting chunks and individual edits to produce a short, 1-minimal trace.

The shrinker reduced an incorrect test assumption to a single rename: source records are retained across filename changes, rather than renamed in place. The oracle was corrected to preserve the old source record and check the new one. This was a test-harness correction, not a product defect (`random-first.log`). An initial test timeout was a string passed to Vitest's numeric timeout option; it was corrected before interpreting randomized results (`attempt1.log`). No product fix was retried more than twice on an unresolved problem.

The randomized test then found a product failure and shrank it to two edits: change the nested child's greeting writer, then extend the outer file along the child's replacement path. The outer file adopted the child's occupied name slot and lost its own imported/local naming choice (`placement-second.log`). Three regular imported-name/local-name/local-clear regressions failed first (`collision-before.log`). Message matching now starts an independent path at an incompatible naming collision before the file's own remembered slot, preserving both records' choices without rewriting the child's slot. Parent extension after its own remembered slot still shares the child continuation, as the supplied N4 repro requires.
