**Status:** Reference, 2026-10-12: SillyTavern 1.19.0's keyword activation, extracted from its public source

The table below records ST's results, not the matcher’s results where a feature is deferred. Every row has a numbered unit test, with explicit alternate expectations and explanations where needed.

Current departures: activation has deterministic aggregate work limits and returns completed admissions with an issue when a limit is reached. Regex compilation has deterministic cache, source-size and repetition-expansion limits. Regex work is capped per key and per activation; a last-resort VM timeout marks the result as not replayable. Oversized slash patterns are refused before syntax validation, including malformed ones that ST would treat literally. Repeated issues are summarized with counts and bounded examples. Sticky/cooldown, identity filters, expanding-history minimum activations, source tiers and decorators are deferred. Unsupported retained activation controls produce issues. The caller supplies resolved keys/content, names, descriptions, scannable injections and an absolute token allowance. Probability and exact-budget rejection follow ST despite the recommendations later in this reference. Book settings and fresh-install defaults are our runtime policy; the test table deliberately overrides them to isolate ST rules.

## Scope and interpretation

This document is an activation reference, **not a requirement to reproduce ST's whole pipeline**. Imported books must work; exact ST activation and placement parity is outside the goal. Our layouts place lore in one volatile block near the tail; retention until compaction is deferred with LCM. ST-compatible mode preserves kept ST positions. The owner explicitly chose ST keyword syntax: **ignore `use_regex`; recognize regular expressions only through ST's `/pattern/flags` parser**. [DESIGN.md:40](DESIGN.md)

There are three distinct objects:

- ST runtime entries use `key`, `keysecondary`, `disable`, camelCase controls and numeric enums. In this document, code describing ST uses those names.
- Our `LorebookEntry` uses `keys`, `secondary_keys`, **`enabled = !disable`**, snake_case controls and named enums. The test table uses our names. Each entry's identity is **book + uid**, not uid alone. ## 1. Key matching rules

### 1.1 Plain strings versus regex

For each primary key, ST calls `substituteParams(key)`, checks that the result is truthy, then passes **`.trim()`** into `buffer.matchKeys`. Secondary keys take the same substitution/trimming path. Keys in an entry's array are independent strings; the matcher itself does **not** split them on commas. A comma typed into the UI is a separate editing concern. [WI:4913–4917](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L4913-L4917) [WI:4943–4948](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L4943-L4948)

`parseRegexFromString(input)` accepts only `^/([\w\W]+?)/([gimsuy]*)$`: a **nonempty** pattern between slashes, optionally followed by only `g i m s u y`. Flags `d` and `v` are rejected even if the JS runtime supports them. An unescaped inner slash detected by `pattern.match(/(^|[^\\])\//)` rejects the string. The check is based on the immediately preceding character, not a complete backslash-parity parser. The implementation replaces only the first `\/` with `/`, then constructs `new RegExp(pattern, flags)` in a `try/catch`. Duplicate flags or invalid syntax return null. **Every parse failure falls back to plain literal matching of the entire trimmed key**, including its slashes/flags; it does not disable the entry or throw. `//` is plain text. [WI:2901–2926](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L2901-L2926) [WI:337–365](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L337-L365)

When parsing succeeds, ST does **`newRegex.test(rawHaystack)`**, bypassing both case and whole-word controls. `i` determines regex case handling. Each call constructs a fresh RegExp, so `g`/`y` lastIndex does not carry between keys, entries or scans. Regex anchors see the buffer's sentinel characters and newlines, not bare chat strings. [WI:337–347](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L337-L347) [WI:295–327](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L295-L327)

**Kept today:** `keys`, `secondary_keys`, `use_regex` (boolean) are stored. ST's activation never reads `use_regex`; our owner says to ignore it. Do not turn a plain `c.t` into a regex because that field is true. ### 1.2 Case sensitivity

For plaintext, the effective setting is **`entry.caseSensitive ?? world_info_case_sensitive`**. False is a real override; null/undefined inherits. If insensitive, ST runs JavaScript `.toLowerCase()` on both haystack and needle; there is no accent folding, locale setting or Unicode normalization. Regex bypasses this transformation. [WI:268–271](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L268-L271) [WI:337–347](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L337-L347)

**Kept today:** nullable `case_sensitive`. Global case preference is **not** in `LorebookDoc`; the implementer must choose a runtime fallback (recommend false). Our embedded-book importer deliberately falls back to the spec's `case_sensitive`, while ST only reads `extensions.case_sensitive`. Thus ST outcomes after importing that format can differ even before matching. ### 1.3 Whole-word matching

Effective setting: **`entry.matchWholeWords ?? world_info_match_whole_words`**. When false, plaintext uses `haystack.includes(transformedKey)`. When true:

1. Split the key on `/\s+/` only to count pieces; **do not normalize its whitespace**.
2. If there is more than one piece, still use `.includes(exactTransformedKey)`; **multiword phrases do not receive word boundaries**.
3. Otherwise construct `(?:^|\W)(escapedKey)(?:$|\W)` with **no flags**. ST's helper escapes regex punctuation, so punctuation in a plain key stays literal.

Consequences: `cat` matches `(cat)!`, but not `_cat_`; underscore and ASCII digits/letters count as word characters. `red fox` matches `tired foxes`, but not `red  fox`. `C++` matches at an end boundary, but not `C++x`. JavaScript's unflagged `\W` treats accented letters and CJK as nonword: `cat` matches `écaté`, and `東京` matches inside `東京都`, while `a東京b` fails. This is **not a Unicode word-segmentation algorithm**. [WI:345–365](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L345-L365) [public/scripts/utils.js:1377–1379](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/utils.js#L1377-L1379)

**Kept today:** nullable `match_whole_words`. No global word preference in our book. Recommend the **fresh-install fallback true** if imports should behave like a fresh ST install, retaining per-entry false overrides; document this runtime choice explicitly. ## 2. Scan input and depth

`checkWorldInfo` receives an array of strings **newest first**. The buffer trims each available string and retains at most the first **1000** positions. Scan depth is a **message count**, not turns, roles, tokens or ST placement depth: `slice(0, depth)` means depth=2 reads indices 0 and 1. Null entry override uses global depth + min-activation skew. Explicit `entry.scanDepth` overrides both. Depth>1000 is clamped. **Depth<=0 returns the empty string before adding any descriptions, prompt injections or recursive content**. This still lets regex `/^$/` match the empty buffer. [WI:240–260](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L240-L260) [WI:279–327](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L279-L327) [WI:395–404](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L395-L404) [WI:4700–4712](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L4700-L4712)

The exact chat portion is **`"\x01" + messages.slice(0,depth).join("\n\x01")`**. Each added description/injection/recursive block is separated by `"\n\x01"`. There is a sentinel even with no chat messages if depth>0. Keys do not implicitly cross message boundaries as plain phrases, but regex `s` can span them; `^cat$` does not match the single-message raw buffer because it starts with `\x01`. [WI:295–327](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L295-L327)

The main caller constructs `coreChat` from messages excluding `is_system`, except system records with tool-invocation arrays when tool calling is supported. It removes the newest core message for **swipe**. Both user and assistant messages remain; there is no keyword-only user-message filter. Before scanning it applies prompt regex scripts, appends file content and opted-in media titles, and may include configured reasoning in message text. Generation interceptors can alter the prepared core messages. Thus "text scanned" means **prepared prompt-side core messages**, not necessarily original stored `mes`, and not the already budget-cut final request. [WI:4700–4712](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L4700-L4712) [public/script.js:4493–4529](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/script.js#L4493-L4529) [public/script.js:4531–4567](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/script.js#L4531-L4567)

## 4. Recursion and minimum activations

**Recursive scanning:** when enabled, successful new candidates without `preventRecursion` cause another scan. Their **macro-substituted content**, joined by newline, is added to the persistent recursion buffer. Later scans search original selected messages + opted-in descriptions + injections + that buffer. Each `(world,uid)` can activate only once in the evaluation; failed probability entries stay failed. A constant entry's content can seed a chain. Recursion never adds extra history depth by itself. ## 5. Timed effects: sticky / cooldown / delay

Timers count **length of the supplied prepared chat array**, not selected scan-depth messages, tokens, wall-clock time or assistant turns. ## 6. Inclusion groups, scoring and weights

Groups run on **new candidates**, before their probability rolls and budget admission. ST splits a nonempty `group` on `/,\s*/`, filters empty names, and adds the same entry to each group; it does not trim arbitrary leading/trailing whitespace on all group names. No group means no mutual exclusion. [WI:5012](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L5012) [WI:5388–5419](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L5388-L5419)

Selection order:

1. Timed effects remove nonsticky competitors when there are sticky entries; such groups skip subsequent scoring and selection. More than one sticky entry can survive, so it is not universally "one per group". Cooldown/delay removal has the quirk described above. [WI:5337–5377](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L5337-L5377) [WI:5424–5429](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L5424-L5429)
2. Scoring runs if global `world_info_use_group_scoring` is true **or** at least one group entry opts in. Compute every entry's score; take the maximum across **all** group entries. Only entries whose effective `useGroupScoring ?? global` is true get removed for a lower score. An explicitly false entry can survive with a lower score and win the later roll. Sticky groups skip scoring. [WI:5292–5327](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L5292-L5327)
3. If an already-admitted entry has **`x.group === currentGroupName`**, all new entries in that group are removed. This is exact whole-string equality, not membership in its comma-separated names: the across-recursion exclusion check has different semantics for multigroup entries. [WI:5431–5435](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L5431-L5435)
4. If at most one candidate remains, no weighted selection. Otherwise, surviving `groupOverride` entries win priority; sort them by **descending order**, take first. This occurs **after scoring**, so an override can lose to scoring first. [WI:5438–5449](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L5438-L5449)
5. Else weighted random: sum `groupWeight ?? 100`, roll `Math.random()*total`, take the first entry where roll is **<= cumulativeWeight**. Equal weights use current candidate order to define intervals. At all-zero weights roll=0 and first wins. There is no runtime normalization/clamping here. [WI:5451–5474](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L5451-L5474)

Score = number of **matching key slots**, not occurrences in text; duplicate slots can count twice. No primary slots → score=0. Positive secondary logic influences score: AND ANY adds primary+secondary; AND ALL adds secondary only when all secondary slots match; negative modes ignore secondary. **The scoring routine does not check `selective`, trim keys or substitute macros**, unlike candidate activation. Thus scoring may see a different key from the activation routine. [WI:428–473](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L428-L473)

For a single-name group admitted in a prior pass, subsequent recursive candidates are suppressed. ## 7. Order, token budget and output

ST's comparator is **`b.order - a.order`** (higher first). Source tiers affect admission before global order: chat lore first, then persona lore; then character/global tiers according to strategy. Each tier is sorted; evenly combines character/global by order. On a pass, sticky candidates precede other candidates; within each category retain sorted-source order. Equal order is stable through `.sort()`, so source/list order is a tie-break. [WI:88](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L88) [WI:4590–4639](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L4590-L4639) [WI:4993–5006](https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/world-info.js#L4993-L5006)

Budget = **`Math.round(world_info_budget * maxContext / 100) || 1`**, limited by positive global absolute cap. Zero percent therefore produces 1, not zero. This is a separate lore budget, not the final prompt assembly budget. Each candidate first passes probability, then macro expansion of content. ST appends **`content + "\n"` to newContent before testing**. If `tokens(allActivatedText) + tokens(newContent) >= budget`, a non-ignore entry is rejected **in its entirety**, sets overflow, and is not added to activated map. Exact equality fails; no content truncation, no search for a later smaller normal entry.
